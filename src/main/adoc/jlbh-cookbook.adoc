== Timing a Simple Method Call

This is the most basic use case: measuring the latency of a self-contained Java method.

*Goal*: Measure the execution time of `myMethod()`.

*Implement the task (`CallBenchmark.java`)*:

[source,java]
----
package net.openhft.chronicle.jlbh.cookbook;

import net.openhft.chronicle.jlbh.JLBH;
import net.openhft.chronicle.jlbh.JLBHTask;

public class CallBenchmark implements JLBHTask {
    private JLBH jlbh;
    private int counter = 0; // Example state

    @Override
    public void init(JLBH jlbh) {
        this.jlbh = jlbh;
        // Initialize any resources needed by myMethod() here
    }

    @Override
    public void run(long startTimeNs) {
        myMethod(counter++); // Pass some varying input if appropriate
        jlbh.sample(System.nanoTime() - startTimeNs);
    }

    private void myMethod(int input) {
        // Work to be timed.
        // This should ideally be significant enough to dominate the
        // overhead of System.nanoTime() and jlbh.sample().
        // For very short methods, consider batching or alternative microbenchmark tools.
        String.valueOf(input).hashCode(); // Example of a small piece of work
    }

    @Override
    public void complete() {
        // Cleanup resources if any were initialized
    }
}
----

*Set up and run the harness (`MainApp.java`)*:

[source,java]
----
package net.openhft.chronicle.jlbh.cookbook;

import net.openhft.chronicle.jlbh.JLBH;
import net.openhft.chronicle.jlbh.JLBHOptions;

public class MainApp {
    public static void main(String[] args) {
        JLBHOptions options = new JLBHOptions()
                .warmUpIterations(20_000) // Allow for JIT compilation and steady state
                .iterations(200_000)    // Number of measurements per run
                .throughput(100_000)    // Target operations per second
                .jlbhTask(new CallBenchmark());
        new JLBH(options).start();
    }
}
----

*Key Considerations*:
* Ensure the work within `myMethod()` is the primary focus.
Avoid including unrelated logic within the timed section.
* The `throughput` setting influences how often `run()` is called.
If `myMethod()` is very fast, high throughput might be achievable.
If it's slower, adjust throughput accordingly.

== Measuring a Network Round Trip (UDP Loopback)

This recipe demonstrates timing a UDP message send and receive on loopback.

*Goal*: Measure the latency of sending a UDP packet and receiving a response.

*Prerequisite*: A UDP echo server must be running on `localhost:8080`.
A simple echo server (`SimpleUDPEchoServer.java`):

[source,java]
----
package net.openhft.chronicle.jlbh.cookbook;

import java.net.DatagramPacket;
import java.net.DatagramSocket;
import java.io.IOException;

public class SimpleUDPEchoServer {
    public static void main(String[] args) throws IOException {
        System.out.println("UDP Echo Server starting on port 8080...");
        try (DatagramSocket socket = new DatagramSocket(8080)) {
            byte[] buffer = new byte[1024];
            DatagramPacket packet = new DatagramPacket(buffer, buffer.length);
            while (true) {
                socket.receive(packet);
                // Echo back to sender
                socket.send(new DatagramPacket(packet.getData(), packet.getLength(), packet.getAddress(), packet.getPort()));
            }
        }
    }
}
----

TIP: Run this server in a separate process before starting the JLBH client.

*Implement the task (`LoopbackBenchmark.java`)*:

[source,java]
----
package net.openhft.chronicle.jlbh.cookbook;

import net.openhft.chronicle.jlbh.JLBH;
import net.openhft.chronicle.jlbh.JLBHTask;

import java.io.IOException;
import java.io.UncheckedIOException;
import java.net.InetSocketAddress;
import java.nio.ByteBuffer;
import java.nio.channels.DatagramChannel;

public class LoopbackBenchmark implements JLBHTask {
    private JLBH jlbh;
    private DatagramChannel channel;
    // Using a direct ByteBuffer can offer performance benefits for I/O
    private final ByteBuffer outBuffer = ByteBuffer.allocateDirect(32);
    private final ByteBuffer inBuffer = ByteBuffer.allocateDirect(32);

    @Override
    public void init(JLBH jlbh) {
        this.jlbh = jlbh;
        try {
            channel = DatagramChannel.open();
            channel.configureBlocking(true); // For simplicity; non-blocking could also be used
            channel.connect(new InetSocketAddress("localhost", 8080));
        } catch (IOException e) {
            throw new UncheckedIOException(e); // Consider more robust error handling
        }
    }

    @Override
    public void run(long startTimeNs) {
        try {
            outBuffer.clear();
            outBuffer.putInt(0, (int) startTimeNs); // Send some data (optional)
            outBuffer.limit(4);
            channel.write(outBuffer);

            inBuffer.clear();
            channel.read(inBuffer); // Wait for echo
        } catch (IOException e) {
            // In a real benchmark, decide how to handle I/O errors.
            // Re-throwing might halt the benchmark or skew results if not all iterations complete.
            throw new UncheckedIOException(e);
        }
        jlbh.sample(System.nanoTime() - startTimeNs);
    }

    @Override
    public void complete() {
        try {
            if (channel != null) {
                channel.close();
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
----

*Set up the harness (`MainApp.java`)*:

[source,java]
----
package net.openhft.chronicle.jlbh.cookbook;

import net.openhft.chronicle.core.Jvm;
import net.openhft.chronicle.jlbh.JLBH;
import net.openhft.chronicle.jlbh.JLBHOptions;

import java.io.IOException;


public class MainApp {
    public static void main(String[] args) {
        // First, ensure SimpleUDPEchoServer is running.
        // new Thread(() -> { try { SimpleUDPEchoServer.main(null); } catch (IOException e) { e.printStackTrace(); }}).start();
        // Jvm.pause(100); // Give server a moment to start if launched programmatically

        JLBHOptions options = new JLBHOptions()
                .warmUpIterations(10_000)
                .iterations(50_000)
                // Lower throughput for network tests helps avoid queuing in network buffers,
                // giving a clearer picture of the actual round-trip time.
                .throughput(1_000) // Reduced from 10_000 for more stable network results
                // Coordinated Omission is crucial for network tests to capture true send-to-receive latency
                .accountForCoordinatedOmission(true)
                .jlbhTask(new LoopbackBenchmark());
        new JLBH(options).start();
    }
}
----

*Key Considerations*:

* For true network latency, run client and server on different machines connected via a relevant network.
* Consider TCP for connection-oriented tests; its performance characteristics (e.g., Nagle's algorithm, ACK delays) differ from UDP.
* Packet loss and retransmissions (for UDP, if implementing reliability) can heavily affect latency distributions.

== Running Within an Existing Event Loop

JLBH can integrate with Chronicle's event loop mechanism, useful for benchmarking components that are already part of an event-driven architecture.

*Goal*: Execute a JLBH benchmark task on a pre-existing `EventLoop`.

*Implement the task (`EventLoopTask.java`)*:

[source,java]
----
package net.openhft.chronicle.jlbh.cookbook;

import net.openhft.chronicle.jlbh.JLBH;
import net.openhft.chronicle.jlbh.JLBHTask;

public class EventLoopTask implements JLBHTask {
    private JLBH jlbh;

    @Override
    public void init(JLBH jlbh) {
        this.jlbh = jlbh;
        System.out.println("EventLoopTask initialized on thread: " + Thread.currentThread().getName());
    }

    @Override
    public void run(long startTimeNs) {
        // Perform work specific to the event loop context
        jlbh.sample(System.nanoTime() - startTimeNs);
    }

    @Override
    public void warmedUp() {
        System.out.println("EventLoopTask warmed up on thread: " + Thread.currentThread().getName());
    }
}
----

*Set up the harness (`MainApp.java`)*:

[source,java]
----
package net.openhft.chronicle.jlbh.cookbook;

import net.openhft.chronicle.core.threads.EventLoop;
import net.openhft.chronicle.jlbh.JLBH;
import net.openhft.chronicle.jlbh.JLBHOptions;
import net.openhft.chronicle.jlbh.JLBHTask;
import net.openhft.chronicle.threads.MediumEventLoop;
import net.openhft.chronicle.threads.Pauser;

public class MainApp {
    public static void main(String[] args) {
        // MediumEventLoop and Pauser are part of Chronicle Core/Threads
        // Pauser.balanced() tries to balance latency and CPU usage.
        EventLoop eventLoop = new MediumEventLoop(null, "myBenchmarkLoop", Pauser.balanced(), true, null);
        eventLoop.start(); // Start the event loop thread

        JLBHTask task = new EventLoopTask();
        JLBHOptions options = new JLBHOptions()
                .warmUpIterations(10_000) // Warmup happens on the event loop too
                .iterations(100_000)
                .throughput(50_000)
                // accountForCoordinatedOmission defaults to true, which is compatible and required
                // for eventLoopHandler() to function as expected.
                .jlbhTask(task);

        JLBH jlbh = new JLBH(options);
        // Instead of jlbh.start(), install handlers onto the event loop
        jlbh.eventLoopHandler(eventLoop);

        // Keep the main thread alive or wait for completion if necessary.
        // For this example, we'll let it run for a bit then stop the loop.
        // In a real app, the event loop would run for the application's lifetime.
        try {
            Thread.sleep(15_000); // Let benchmark run
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            eventLoop.close(); // Cleanly shut down the event loop
        }
    }
}
----

*Key Considerations*:

* The `eventLoopHandler` method installs handlers that drive the benchmark lifecycle on the `EventLoop`'s thread.
* This is useful when the code being benchmarked is designed to run on a specific event loop.
* `JLBHOptions.accountForCoordinatedOmission(true)` (the default) is essential for `eventLoopHandler` to function correctly.

== Using Multiple Probes for Staged Operations

JLBH allows timing multiple stages within a single benchmark iteration using custom probes.

*Goal*: Measure total operation latency and the latency of two distinct internal stages.

*Implement the task (`MultiStageBenchmark.java`)*:

[source,java]
----
package net.openhft.chronicle.jlbh.cookbook;

import net.openhft.chronicle.core.util.NanoSampler;
import net.openhft.chronicle.jlbh.JLBH;
import net.openhft.chronicle.jlbh.JLBHTask;

import java.util.concurrent.TimeUnit;

public class MultiStageBenchmark implements JLBHTask {
    private JLBH jlbh;
    private NanoSampler stage1Sampler;
    private NanoSampler stage2Sampler;

    @Override
    public void init(JLBH jlbh) {
        this.jlbh = jlbh;
        // Register custom probes for each stage
        this.stage1Sampler = jlbh.addProbe("Stage1_Processing");
        this.stage2Sampler = jlbh.addProbe("Stage2_Persistence");
    }

    @Override
    public void run(long startTimeNs) {
        // Stage 1
        long stage1StartNs = System.nanoTime();
        performStage1Work();
        stage1Sampler.sampleNanos(System.nanoTime() - stage1StartNs);

        // Stage 2
        long stage2StartNs = System.nanoTime();
        performStage2Work();
        stage2Sampler.sampleNanos(System.nanoTime() - stage2StartNs);

        // Sample total end-to-end time
        jlbh.sample(System.nanoTime() - startTimeNs);
    }

    private void performStage1Work() {
        // Simulate some processing work, e.g., data transformation
        try {
            TimeUnit.NANOSECONDS.sleep(100 + (System.nanoTime() % 50)); // Variable work
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }

    private void performStage2Work() {
        // Simulate some I/O or persistence work
        try {
            TimeUnit.NANOSECONDS.sleep(150 + (System.nanoTime() % 70)); // Variable work
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}
----

*Set up the harness (`MainApp.java`)*:

[source,java]
----
package net.openhft.chronicle.jlbh.cookbook;

import net.openhft.chronicle.jlbh.JLBH;
import net.openhft.chronicle.jlbh.JLBHOptions;

public class MainApp {
    public static void main(String[] args) {
        JLBHOptions options = new JLBHOptions()
                .warmUpIterations(15_000)
                .iterations(100_000)
                .throughput(20_000) // Adjust based on expected stage latencies
                .jlbhTask(new MultiStageBenchmark());
        new JLBH(options).start();
    }
}
----

*Key Considerations*:

* The sum of individual probe latencies might not exactly equal the end-to-end latency due to the overhead of `System.nanoTime()` calls between stages.
* This approach is excellent for identifying bottlenecks within a larger operation.
* The JLBH output will include separate percentile summaries for "Stage1_Processing", "Stage2_Persistence", and the default "end to end" probe.

== Recording and Exporting Results

JLBH allows programmatic access to results and provides utilities for serialization, such as to CSV.

*Goal*: Run a benchmark, retrieve its results, and save them to a CSV file.

*Implement the task*: We can reuse the `CallBenchmark` from Recipe 1.

[source,java]
----
// Re-use CallBenchmark.java from Recipe 1
package net.openhft.chronicle.jlbh.cookbook;
import net.openhft.chronicle.jlbh.JLBH;
import net.openhft.chronicle.jlbh.JLBHTask;
public class CallBenchmark implements JLBHTask { ... }
----

*Set up the harness and process results (`MainApp.java`)*:

[source,java]
----
package net.openhft.chronicle.jlbh.cookbook;

import net.openhft.chronicle.jlbh.JLBH;
import net.openhft.chronicle.jlbh.JLBHOptions;
import net.openhft.chronicle.jlbh.JLBHResult;
import net.openhft.chronicle.jlbh.JLBHResultConsumer;
import net.openhft.chronicle.jlbh.util.JLBHResultSerializer;

import java.io.IOException;
import java.time.Duration;

public class MainApp {
    public static void main(String[] args) {
        JLBHResultConsumer resultConsumer = JLBHResultConsumer.newThreadSafeInstance();

        JLBHOptions options = new JLBHOptions()
                .warmUpIterations(10_000)
                .iterations(50_000)
                .throughput(100_000)
                .jlbhTask(new CallBenchmark()) // Using CallBenchmark from Recipe 1
                .runs(2); // Multiple runs to see more in the result

        // Pass the consumer to the JLBH constructor
        new JLBH(options, System.out, resultConsumer).start();

        // After JLBH completes, retrieve the results
        JLBHResult result = resultConsumer.get();

        if (result != null) {
            // Programmatically access results (example: last run's 99th percentile)
            JLBHResult.RunResult lastRunEndToEnd = result.endToEnd().summaryOfLastRun();
            Duration p99 = lastRunEndToEnd.get99thPercentile();
            System.out.printf("Last run's End-to-End 99th Percentile: %d ns%n", p99.toNanos());

            // Serialize all probe results to CSV
            try {
                String csvFileName = "benchmark_results.csv";
                JLBHResultSerializer.runResultToCSV(result, csvFileName, result.probeNames(), true);
                System.out.println("Benchmark results saved to " + csvFileName);
                // The CSV file will contain:
                // ProbeName,50th p-le,90th p-le,99th p-le,999th p-le,9999th p-le,Worst
                // endToEnd,...
                // (any other custom probes)...
                // OSJitter,... (if enabled)
            } catch (IOException e) {
                System.err.println("Error saving results to CSV: " + e.getMessage());
                e.printStackTrace();
            }
        } else {
            System.err.println("Benchmark did not produce results.");
        }
    }
}
----

*Key Considerations*:

* `JLBHResultConsumer.newThreadSafeInstance()` is important if you plan to access results from a different thread than the one running `JLBH.start()`, though in this synchronous example it primarily serves as the hook.
* The `JLBHResult` object is immutable and contains rich data for all probes and runs.
* `JLBHResultSerializer` provides a convenient way to get data out for external analysis.

== Enabling and Understanding OS Jitter Measurement

Operating system jitter can significantly impact low-latency applications.
JLBH can measure this independently.

*Goal*: Configure JLBH to record OS jitter and understand its output.

*Implement the task*: Any simple task will do, as OS jitter is measured by a background thread.
We'll reuse `CallBenchmark`.

[source,java]
----
// Re-use CallBenchmark.java from Recipe 1
----

*Set up the harness with OS Jitter options (`MainApp.java`)*:

[source,java]
----
package net.openhft.chronicle.jlbh.cookbook;

import net.openhft.chronicle.jlbh.JLBH;
import net.openhft.chronicle.jlbh.JLBHOptions;

public class MainApp {
    public static void main(String[] args) {
        JLBHOptions options = new JLBHOptions()
                .warmUpIterations(5_000) // Shorter for quick demo
                .iterations(10_000)   // Shorter for quick demo
                .throughput(50_000)
                .jlbhTask(new CallBenchmark())
                // OS jitter recording is enabled by default; use recordOSJitter(false)
                // if you want to disable the background monitor.
                // Optional: Only record jitter events greater than a specific threshold (default 1_000 ns)
                // .recordJitterGreaterThanNs(5_000)
                // Optional: Pin the OS Jitter monitoring thread to a specific CPU core (if supported)
                // .jitterAffinity(true) // Be cautious with affinity, ensure free isolated cores
                .runs(1);

        new JLBH(options).start();
    }
}
----

*Interpreting OS Jitter Results*:

* JLBH records OS jitter by default and starts a background thread that continuously measures the time elapsed between calls to `System.nanoTime()`.
Use `recordOSJitter(false)` only when you want to suppress this monitoring.
* If this measured gap exceeds `recordJitterGreaterThanNs`, it's considered an OS-induced pause/jitter event and is recorded in a special "OS Jitter" probe.
* The JLBH output (both console and `JLBHResult`) will include a section for the "OS Jitter" probe, showing its own percentile distribution.
* These jitter values represent pauses that are *not* caused by your application code but by the operating system or other processes interfering with the JLBH process's execution.
* High OS jitter values (e.g., milliseconds) can explain unexpected latency spikes in your main application probes, even if your application code itself is highly optimized.

*Key Considerations*:

* OS jitter measurement adds some (usually small) overhead.
Enable it when you suspect external factors are influencing your benchmark.
* The `recordJitterGreaterThanNs` option helps filter out minor, expected system noise.
* `jitterAffinity(true)` can provide more stable jitter measurements if you have isolated CPU cores available, but can be detrimental otherwise.
* Correlating high OS jitter percentiles with high application latency percentiles can be a powerful diagnostic tool.
